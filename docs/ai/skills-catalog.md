# AI Skills Catalog

このドキュメントは、プロジェクト内で利用するAIスキルの定義一覧です。
将来的な `SKILL.md` 実体化を前提に、目的・入力・手順・成果物を先に固定します。

## 1. spec-writer（仕様整理）

- **目的**: 要件・制約・受け入れ条件を曖昧さなく整理し、実装可能な仕様へ落とし込む。
- **主な入力**:
  - Issue / 要望文
  - 既存仕様（`docs/specs` 配下）
  - 関連コード
- **主な出力**:
  - 仕様サマリ
  - 非機能要件・制約一覧
  - 受け入れ条件（Given/When/Then 形式推奨）
  - 未確定事項と確認質問
- **基本ワークフロー**:
  1. 要求を「目的 / スコープ / 非スコープ」に分解
  2. 既存仕様・実装との差分を抽出
  3. テスト可能な受け入れ条件へ変換
  4. リスクとオープンクエスチョンを列挙
- **完了条件**:
  - 実装担当が追加質問なしで着手できる。

## 2. kotlin-layer-guard（依存ルール監査）

- **目的**: Kotlinプロジェクトのレイヤ依存ルール（例: Domain→Infra禁止）を継続的に監査する。
- **主な入力**:
  - ソースコード（`projects/crypto-autotrading-app`）
  - アーキテクチャ規約
  - build設定
- **主な出力**:
  - 依存違反の一覧（違反箇所・理由・修正案）
  - 監査結果サマリ（OK / NG）
  - ルールの自動検査案（detekt / ArchUnit / custom script 等）
- **基本ワークフロー**:
  1. パッケージ層と依存方向の定義確認
  2. import / 型参照 / build依存を点検
  3. 違反を「重大度」と「修正容易性」で分類
  4. 再発防止の機械検査を提案
- **完了条件**:
  - 依存違反が再現可能な根拠付きで報告される。

## 3. trading-safety-review（損失制御観点）

- **目的**: 自動売買ロジックを損失制御・異常時安全性の観点でレビューする。
- **主な入力**:
  - 売買戦略仕様
  - リスク設定（最大ポジション、ストップ条件等）
  - 実装・テストコード
- **主な出力**:
  - リスクシナリオ別レビュー結果
  - 防御策の不足点と優先度
  - 監視アラート / フェイルセーフ提案
- **基本ワークフロー**:
  1. 想定損失シナリオ（急変・流動性低下・API障害）を列挙
  2. 既存制御（SL/TP、サーキットブレーカー、注文上限制御）を検証
  3. 「検知」「抑制」「停止」「復帰」の観点でギャップ分析
  4. 追加テスト（異常系・境界値）を提示
- **完了条件**:
  - 重大損失につながる未対策リスクが明確化され、具体的対策が提案される。
