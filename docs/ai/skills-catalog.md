# AI Skills Catalog

## 概要

本ドキュメントは、プロジェクト内でAIエージェントが提供可能な特定の専門スキルとその入出力仕様を定義しています。要件定義やコード監査など、特定のタスクを実施する際に参照します。

## 適用対象

要件定義や高度な監査を行うAIエージェント

## 必ず読む関連ドキュメント

[agents-guidelines.md](agents-guidelines.md)

本ドキュメントは、プロジェクト内でAIが提供可能な特定の専門スキルとその入力・出力仕様を定義する。

## 1. spec-writer（仕様策定支援）

- **目的**: 曖昧な要件を実装・検証可能な仕様に落とし込む。
- **入力**: ユーザーからのIssueや要望文、既存の仕様書（`docs/overview/`, `docs/architecture/` 等）、関連コード。
- **出力**: 仕様サマリ、制約一覧、テスト可能な受け入れ条件、未確定事項のリスト。
- **ルール**: 推測で仕様を決定しないこと。不明点は必ず質問として挙げる。

## 2. kotlin-layer-guard（Kotlin依存関係監査）

- **目的**: Kotlinプロジェクトの厳格なレイヤ依存ルールを監視し、違反を検出する。
- **入力**: `projects/crypto-autotrading-app` のコード、ビルド設定。
- **出力**: 依存違反のリスト（箇所・理由）、修正コード案、再発防止策の提案。
- **ルール**: 単なる指摘に留めず、必ず具体的な修正コードの差分を提示すること。

## 3. trading-safety-review（自動売買リスク監査）

- **目的**: 取引ロジックを損失制御（フェイルセーフ）の観点でレビューする。
- **入力**: 戦略仕様、リスク設定コード。
- **出力**: リスクシナリオ別の評価、防御策の不足点の指摘、異常系テストケースの提案。
- **ルール**: 「利益を上げる」観点ではなく、異常事態（API障害、急変等）における「損失を防ぐ」観点に特化すること。

## 4. kotlin-readable-code（Kotlin可読性ガード）

- **目的**: Kotlinコードを、読みやすさ・安全性・保守性を優先して実装・レビューする。
- **入力**: `projects/crypto-autotrading-app` のKotlinコード、変更依頼、関連テスト。
- **出力**: 読みやすいKotlin実装、Scope functions使用理由、拡張関数の配置理由、可読性レビュー結果。
- **ルール**: `let` / `run` / `with` / `apply` / `also` や拡張関数は、コードの意図が明確になり、直感的に読める場合は積極的に使う。ただし、処理の流れ・責務・戻り値が分かりにくくなる場合は、通常の関数、明示的な変数名、`if`、`return` を優先する。

## 禁止事項

各ルールの詳細および `agents-guidelines.md` の絶対禁止操作を参照すること。

## 判断に迷った場合

推測で判断せず、ユーザーに確認を求めること。

## 完了報告の形式

`prompt-template.md` で定義されたフォーマットを厳守すること。
