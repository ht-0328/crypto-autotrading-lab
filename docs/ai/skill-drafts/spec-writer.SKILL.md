# Skill: spec-writer

## Purpose
要求を実装可能・検証可能な仕様へ整理する。

## When to use
- 機能追加や仕様変更の要望を受けたとき
- 要件が曖昧で、実装前に合意文書が必要なとき

## Inputs
- 要望文（Issue, チャット, メモ）
- 既存仕様書（`docs/specs`）
- 関連コード

## Workflow
1. 要望を「目的・スコープ・非スコープ」に分解。
2. 既存仕様との矛盾・不足を抽出。
3. 受け入れ条件をテスト可能な形（Given/When/Then）に変換。
4. 未確定事項と確認質問を作成。

## Output
- 仕様サマリ
- 受け入れ条件
- 制約・前提
- オープンクエスチョン

## Done criteria
- 実装担当が追加質問なしで着手可能。
