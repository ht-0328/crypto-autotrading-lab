# PRレビュー チェックリスト

このチェックリストは、`crypto-autotrading-lab` のPRレビュー時に最低限確認する観点をまとめたものです。

## 1. レイヤ依存違反
- [ ] `domain` レイヤがIO実装（HTTPクライアント、ファイル操作、DB、環境変数直接参照）を持っていない
- [ ] `infrastructure` の詳細実装が `domain` の責務を侵食していない
- [ ] 依存方向が `presentation -> application/infrastructure -> domain` を崩していない
- [ ] ドメインロジックの条件分岐がUI/外部API都合で汚染されていない

## 2. 設定互換性
- [ ] `config/application-*.yaml` の既存キー名・意味を破壊していない
- [ ] 設定のデフォルト値変更に伴う影響が説明されている
- [ ] 新規設定キーが未設定でも安全に動作する（または明確に失敗する）
- [ ] 環境差分（GMO / WireMock / local docker）を考慮している

## 3. ログ/監査性
- [ ] 重要イベント（起動、判定、保存、エラー）がログで追跡できる
- [ ] 失敗時に原因特定に必要な文脈（対象、入力、例外種別）が残る
- [ ] 機密情報（APIキー、シークレット、個人情報）をログ出力していない
- [ ] CSV/JSONなど監査対象の出力形式変更時に互換性や移行方針が示されている

## 4. 例外処理
- [ ] 例外の握りつぶし（空catch、無言リトライ）がない
- [ ] リトライ有無・中断条件が妥当で、無限ループを作っていない
- [ ] ユーザー/運用者が次アクションを判断できるエラーメッセージになっている
- [ ] 失敗時の状態不整合（中途半端な保存、重複出力）が発生しない

## 5. レビュー結論
- [ ] 受け入れ条件を満たしている
- [ ] 追加で必要なテスト/ドキュメント更新が洗い出されている
- [ ] マージ後の運用リスクとロールバック方針が明確
