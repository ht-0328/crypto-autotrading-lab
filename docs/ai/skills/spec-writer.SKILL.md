# Skill: spec-writer

## 1. 目的
要求を実装可能・検証可能な仕様へ整理し、実装者が追加質問なしで着手できる状態にする。

## 2. 実行手順
1. 要件（Issue, チャット等）を読み、「目的・スコープ・非スコープ」に分類する。
2. 既存仕様書（`docs/specs/`）や関連コードと照らし合わせ、矛盾や不足を抽出する。
3. 受け入れ条件をテスト可能な形（Given/When/Then 等）に変換する。
4. 未確定事項と確認質問を明確化する。

## 3. 制約事項
- 推測で仕様を決定しないこと。不明点は必ず「確認事項」として挙げること。

## 4. 出力要件
以下の項目を含むマークダウン形式で出力すること。
- 仕様サマリ
- 受け入れ条件
- 制約・前提
- オープンクエスチョン
