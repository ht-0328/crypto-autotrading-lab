## 文書の目的

- タスク（やること）の整理方法
- プログラムを書くときの注意点
- PR（Pull Request）の作り方とレビューのポイント
- コードを合流（マージ）してリリースする基準

## 対象読者

開発メンバー

## 概要

毎日の開発は「小さな変更を確実にメインのコードに合流させる（マージする）」ことを目標に進めます。直接メインのコードを書き換えるのは禁止です。

## 1. タスクの整理（Backlogの整備）

その日に何を終わらせるかを決めます。ここが決まってから、以降の段階に進みます。

### やること

- 今日やるタスクを1〜3件選びます。
- タスクの「目的」と「どこまでやったら終わりか（完了条件）」をはっきりさせます。口頭だけの依頼で作業を始めないでください。

### 完了条件

- [ ] 今日やるタスクと完了条件が誰が見ても分かる状態になっている。

## 2. プログラムの実装と確認

コードを書き、自分の環境で動くところまで確認します。ドキュメントを触った場合の追加手順もここにあります。

### やること

- タスクの内容に沿ってプログラムを書きます。
- 書いたコードが、他の関係ない部分を壊していないか（副作用）確認します。
- 自分のパソコン（ローカル環境）で動かしてテストします。

### ドキュメントを追加・移動・削除したとき

`docs/` 配下の Markdown を触ったときは、次の2つを必ず行ってください。どちらも忘れると公開サイト側だけが壊れ、GitHub 上では気付けません。

1. [zensical.toml](https://github.com/ht-0328/crypto-autotrading-lab/blob/main/zensical.toml) の `nav` を更新する。`nav` に無いファイルは公開サイトの目次に出ません。
2. `python3 scripts/check-doc-links.py` を実行する。`docs/` の外を指す相対リンクが残っていると、検出されて終了コード 1 を返します。

書き方のルールは [ドキュメントリンク方針](../README.md) を参照してください。

### 完了条件

- [ ] 変更した理由を説明できる。
- [ ] ローカル環境で最低限のテストをして、動くことが確認できている。
- [ ] `docs/` を変更した場合、`nav` を更新し `python3 scripts/check-doc-links.py` が通っている。

## 3. PR（Pull Request）とコードレビュー

他の人が読める形に整えて、レビューを受けます。

### やること

- コードの変更を提案する「PR」を作ります。「目的・変更点・確認方法・リスク」を書いてください。
- チームメンバーにコードを見てもらい（レビュー）、以下の点を確認します。
  - 仕様通りに動くか
  - 安全か（秘密情報が漏れていないかなど）
  - 読みやすいコードか
  - テストが書かれているか

### 完了条件

- [ ] レビューでもらった指摘をすべて直している。
- [ ] 自動テスト（CI）に合格している。

## 4. マージ（合流）の実施

レビューを通った変更を main に合流させます。

### やること

- 承認されたPRだけをメインのコード（mainブランチ）に合流させます。
- マージが終わったら、タスク管理ツール（Issueなど）を「完了」にします。

### 完了条件

- [ ] マージした後も、メインのコードのテストが通っている。
- [ ] 終わったタスクが分かるように記録されている。

## 5. リリースの判定

合流した変更を実際の環境に反映するかどうかを、その日のうちに決めます。

### やること

- その日マージしたコードを、実際の環境（本番環境など）に反映（リリース）するかどうか決めます。
- 「ユーザーに影響はあるか」「問題が起きたらすぐ戻せるか」を考えて判断します。リリースしない場合は理由を残します。

### 完了条件

- [ ] 「リリースする / しない」の判断が記録されている。
- [ ] 次の日にやるべきことが決まっている。

## 用語補足

- **PR (Pull Request)**: 書いたコードの確認と合流を依頼する仕組み。
- **CI**: コードを合流させる前に、自動でテストをして問題がないか確認する仕組み。
- **マージ**: 自分の書いたコードを、みんなが使うメインのコードに合流させること。
- **リリース**: 完成したコードを実際の環境に反映させること。

## 更新方針

システムの要件や運用フローが変更された際に更新してください。
