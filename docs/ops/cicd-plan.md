# CI/CD 導入計画

## 目的

* 実装前に CI/CD の段階導入方針を明確化し、運用リスクを抑える。
* 初期は品質担保を最優先とし、デプロイ自動化は後段で安全に追加する。

## 方針

### Phase1: CI のみ導入

Phase1 では **CI のみ**を対象とし、以下のチェックを Pull Request ごとに実行する。

* build
* lint
* test
* format
* check

#### Phase1 の狙い

* コード品質の自動検証を先に安定化する。
* 失敗要因を「実装品質」と「デプロイ手順」に分離し、問題切り分けを容易にする。
* 開発フロー（レビュー/修正/再実行）をチームで定着させる。

### Phase2: CD を追加

Phase2 で CD（デプロイ自動化）を追加する。

* CI が安定稼働していることを前提にする。
* デプロイ対象環境・承認フロー・ロールバック手順は `docs/ops/release-strategy.md` の合意内容に従う。

## 導入順序

1. CI ワークフローを先に整備（build/lint/test/format/check）
2. CI の失敗傾向と所要時間を観測し、基準値を決める
3. リリース戦略文書に沿って CD 設計を確定
4. Phase2 で CD を段階的に有効化

## 合意ポイント

* まずは「壊れたコードを main に入れない」ことを最優先にする。
* デプロイ自動化は、手動承認ゲートとロールバック条件の合意後に実施する。
