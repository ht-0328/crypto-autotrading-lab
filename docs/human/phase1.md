# Phase1 仕様書（シミュレーション基盤の構築）

## フェーズの位置づけ

Phase1は、安全を最優先とし、実資金による実際の注文を行わない「シミュレーション環境」を構築するためのフェーズです。
プロダクト全体における共通の要求事項は [プロダクト要求仕様](./product-requirements.md) を正本として参照してください。本書では、Phase1 固有の仕様のみを定義します。

## Phase1 のスコープと要件

* **対象取引所**: GMOコイン
* **対象通貨**: BTC
* **利用API**: Public API のみを利用する（認証不要なデータ取得のみ）
* **アプリケーション形態**: Kotlinベースの CLI（コマンドライン）アプリケーション
* **実行環境**: ローカルの Docker または Docker Compose を用いて実行できること
* **開発環境**: VS Code の devcontainer 上でビルドおよび実行が可能であること
* **主要機能**:
  * 現在価格および過去足（Klines）のデータを取得すること
  * 取得したデータに基づいて売買判定を行い、その結果をコンソールに出力すること
  * 判定結果や価格の履歴を CSV 形式で保存すること
  * アプリケーションの実行状態（ポジションの有無など）を JSON 形式のファイルとして保存すること

## 技術スタックと方針

* **開発言語**: Kotlin（取引ロジックやメインシステムはKotlinで統一）
  * 将来的にデータ分析用途に限定してPythonの追加導入を検討する可能性があります
* **ビルドツール**: Gradle (Kotlin DSL を使用)
* **HTTPクライアント**: Ktor Client
* **JSONシリアライザ**: kotlinx.serialization
* **ロギング**: Kotlin Logging + logback
* **設定ファイルフォーマット**: YAML
* **状態保存フォーマット**: JSON

## パッケージ構成と依存ルール

アプリケーション本体（`projects/crypto-autotrading-app/src/main/kotlin/cryptoautotrading/`）のパッケージ構成は以下のように定めます。

| パッケージ名                  | 役割                                      |
| ----------------------------- | --------------------------------------- |
| `presentation`                | アプリケーションのエントリーポイント（`main`関数）、CLIの起動処理を担う |
| `application`                 | 定期実行（5分ごと）の制御、1回分の処理フロー全体のオーケストレーション |
| `domain.strategy`             | 買い候補・売り候補・見送りなどの売買判定ルールをカプセル化する        |
| `domain.simulation`           | 仮想資金の管理、保有状態の管理、損益計算、シミュレーション状態の更新を行う |
| `domain.model`                | システムの中心となるデータ型（判定結果、価格情報、状態モデルなど）を定義する |
| `infrastructure.exchange.gmo` | GMOコインの Public API との通信、およびAPIレスポンスからドメインモデルへの変換 |
| `infrastructure.config`       | `application.yaml` の読み込みと設定値オブジェクトへの変換を担う   |
| `infrastructure.output`       | コンソール出力、CSVファイル出力、`state.json` への状態保存などのI/Oを担当 |
| `shared`                      | アプリケーション全体で利用される共通例外、ユーティリティ、定数を配置する    |

### 依存関係のルール（アーキテクチャ制約）

* `domain` パッケージは、HTTP通信、YAMLの読み込み、ファイルの保存（CSV/JSON）といった外部I/O処理に直接依存してはいけません。
* 外部との入出力処理はすべて `infrastructure` パッケージが担当します。
* `application` パッケージは処理の順序（フロー）を組み立てることに専念し、ビジネスロジックを含んではいけません。
* `presentation` パッケージは起動時の処理のみに限定します。
* 売買の判定ロジックは必ず `domain.strategy` に配置し、状態更新や損益計算は `domain.simulation` に配置します。

## アプリケーションの実行フロー

Phase1 では、アプリケーションは5分ごとに以下の流れを1サイクルとして実行します。

1. 設定ファイル（YAML）を読み込む。
2. GMOコインの Public API から最新の価格データを取得する。
3. 取得した価格データをもとに、売買の判定ロジックを実行する。
4. 判定結果に基づき、シミュレーションの状態（仮想資金や保有ポジション）を更新する。
5. 実行結果をコンソールへ出力する。
6. 今回の実行履歴をCSVに追記し、最新の状態をJSONファイルへ保存する。

## 実行仕様とロジック

* **実行間隔**: 5分ごとに定期実行する（アプリケーション自身が5分間隔でループして動作する設計）。
* **基準足**: 5分足ベースで動作する。
* **データ参照**: 直近12本（1時間分）の5分足データを参照して判定を行う。

### 売買ロジックの初期設定

本アプリケーションは `TradingStrategy` インターフェースを利用したStrategyパターンで取引ロジックを管理しています。戦略は設定ファイル（`trading.strategy_name`）や環境変数（`APP_TRADING_STRATEGY_NAME`）で切り替えることが可能です。

* **初期仮想元本**: 10,000円
* **1回の売買金額**: 1,000円固定
* **ポジション上限**: 同時に持てるのは1ポジションのみ
* **現在の戦略（デフォルト）**: `SafeReboundStrategy`
  * エントリー: 現在価格が基準値より下落し、かつ急落・急騰といった危険な相場でない場合に買い候補と判定。
  * イグジット（利確・損切り）: ポジション保有時は、買値（`buyPrice`）を基準に一定割合の利益・損失に達した時点で売り候補と判定。
* **比較用戦略**: `SimpleContrarianStrategy`
  * 開発初期の単純な逆張りロジックです。現在価格が基準値より一定割合上昇したら売り、下落したら買いと判定します。
* **見送り（取引しない）共通条件**:
  * 直近1時間の価格変動が極端に小さい場合（ボラティリティ不足）
  * 直近15分間で急落・急騰している場合（危険回避）
* **ロジックの出力結果ステータス**:
  * 買い候補
  * 売り候補
  * 見送り
  * 保有中

## データの出力仕様

### コンソール出力

* アプリケーションの動作状況はコンソールに出力します。
* 通常時（見送り時）は簡易な表示にとどめます。
* 売買のサイン（買い候補・売り候補）が出た時のみ、詳細な情報を出力します。
* 出力項目: 現在価格、現在の損益、売買サイン、その判定となった理由、想定される損益。

### CSV出力

* **保存先**: リポジトリルート直下の `data/` ディレクトリ。
  * ファイルパスは設定ファイルや環境変数で変更可能とすること。
  * Docker実行時は、ホスト側の `config/` と `data/` ディレクトリをコンテナにマウントして利用します。
* **ローテーション**: 1日につき1ファイル作成する。
* **カラム（列）定義**:
  * 実行日時
  * 現在価格
  * 判定された売買サイン
  * 判定理由
  * 現在の仮想損益
  * ポジションの保有状態
  * 仮想手数料

### 状態ファイル (JSON) 出力

* **保存先**: リポジトリルート直下の `data/state.json`。
  * ファイルパスは設定ファイルや環境変数で変更可能とすること。
* **フォーマット**: JSON
* **保存内容**:
  * 現在ポジションを保有中かどうかのフラグ
  * 買い付けた時点の価格
  * 保有している数量
  * 状態の最終更新日時

## 設定ファイル (YAML) の仕様

* **保存先**: リポジトリルート直下の `config/application.yaml`。
  * ファイルパスは設定ファイルや環境変数で変更可能とすること。
* **フォーマット**: YAML
* **セクション構成**:
  * `app`: アプリケーション全体の基本設定
  * `trading`: 取引ロジックに関するパラメータ
  * `api`: API接続先に関する設定
  * `output`: ファイル出力先などの設定
* 実行のたび（サイクルごと）にファイルを読み直す設計とし、再起動せずとも設定値の変更が反映されるようにします。
