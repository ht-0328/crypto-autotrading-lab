# ロードマップ（PhaseごとのEntry/Exit Criteria）

本ドキュメントは、各Phaseを「着手条件（Entry）」「完了定義（Exit）」「未解決リスク」「禁止事項」で管理するための基準です。

## Phase1（安全なシミュレーション基盤）

### Entry条件（着手条件）

* リポジトリ初期構成（`config/`, `data/`, `docs/`, `projects/`）の方針が合意されている
* 開発環境（devcontainer / Docker / Gradle）が利用可能である
* 利用取引所・通貨・非機能の最小要件（GMOコイン / BTC / ローカル実行）が明確化されている

### Exit条件（完了定義）

* GMOコイン Public API から価格データ（ticker / klines）を取得できる
* 売買判定ロジックが5分足ベースで実行できる
* シミュレーション状態をJSONで保存できる
* 実行ログをCSVとして保存できる
* `./gradlew build` と `./gradlew run` が再現可能である
* `docker compose -f docker/compose/local.yml up --build` で起動確認できる

### 未解決リスク

* API仕様変更時の追従コストが不確実
* 長時間稼働時のメモリ・ログ肥大化対策が未検証
* 相場急変時のルール妥当性（過学習/過剰反応）が未検証

### 禁止事項

* 実注文の送信（Private API 利用を含む）
* 実資金の投入・接続
* 自動売買ボットとしての本番運用

## Phase2（運用可視化と通知強化）

### Entry条件（着手条件）

* Phase1 のExit条件を全て満たしている
* 通知チャネル（LINE等）と画面要件の最小仕様が定義されている
* 設定変更の責務分離（ファイル/画面）が設計レビュー済みである

### Exit条件（完了定義）

* LINE通知で「売買サイン・理由・現在価格・想定損益」を配信できる
* 最低限のWeb画面から稼働状態を確認できる
* 設定値を画面から変更し、反映可否を検証できる
* 主要操作（起動、停止、設定変更、通知確認）の手順書が整備されている

### 未解決リスク

* 通知遅延や欠損時の再送制御が未確立
* UI追加に伴う運用ミス（誤設定）の防止策が不十分
* 認証・認可の深さが将来の本番要件に対して不足する可能性

### 禁止事項

* 自動で実注文を行う機能の有効化
* UIから秘密情報（APIキー等）を平文で保存
* 監査ログなしで重要設定を変更する運用

## Phase3（実注文 + 手動承認 + 安全制御）

### Entry条件（着手条件）

* Phase2 のExit条件を全て満たしている
* 実注文フロー（承認者、承認手順、ロールバック）が文書化されている
* リスク上限（損切り、連続負け停止、1日最大損失）が数値で合意されている

### Exit条件（完了定義）

* 通知→手動承認→実注文の一連フローが本番相当環境で検証済み
* 移動平均ルールを追加し、既存戦略との比較検証結果が記録されている
* 安全条件（損切り、連続負け停止、1日最大損失）が全て強制適用される
* 監査ログに「誰が・いつ・何を承認/実行したか」が残る

### 未解決リスク

* 市場急変・流動性低下時に想定通り約定しないリスク
* 手動承認の遅延によりシグナル劣化が発生するリスク
* 取引所障害時のフェイルセーフ（停止判断）の運用成熟不足

### 禁止事項

* 手動承認なしでの実注文実行
* 安全条件を無効化したままの注文許可
* 障害時に原因未特定のまま取引再開
