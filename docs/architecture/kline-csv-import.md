## 1. 文書の目的

この文書は、バックテストで使用する過去K線CSVを読み込む機能の仕様を定義するものです。

過去K線CSV作成機能で出力したCSVを読み込み、アプリ内で扱える List<Kline> に変換できるようにします。

バックテスト本体は、ここで読み込んだ List<Kline> を使って、売買戦略の動きを検証します。

## 2. 機能概要

この機能は、指定された過去K線CSVファイルを読み込み、バックテストで利用しやすい Kline の一覧として返します。

処理の概要は以下です。

- 指定されたCSVファイルのパスを受け取る
- CSVファイルを読み込む
- ヘッダーが openTime,open,high,low,close,volume の順番であることを確認する
- CSVの各行を Kline に変換する
- openTime の昇順に並べる
- 同じ openTime のデータが重複した場合は1件にまとめる
- バックテスト入力用の List<Kline> として返す

## 3. 入力仕様

この機能は、以下の値を入力として受け取ります。

| 項目                    | 例                                                 | 説明                             |
| ----------------------- | -------------------------------------------------- | -------------------------------- |
| BACKTEST_KLINE_CSV_PATH | data/backtest/input/btc_5min_20260501_20260531.csv | 読み込む過去K線CSVファイルのパス |

入力例:

```
BACKTEST_KLINE_CSV_PATH=data/backtest/input/btc_5min_20260501_20260531.csv
```

## 4. 出力仕様

出力は List<Kline> です。

Kline の1件は、CSVの1行に対応します。
例えば KLINE_EXPORT_INTERVAL=5min で作成されたCSVの場合、Kline の1件は5分間の価格情報を表します。

Kline の項目は以下とします。

| 項目     | 説明                           |
| -------- | ------------------------------ |
| openTime | K線の開始時刻                  |
| open     | その期間の最初の価格           |
| high     | その期間の中で一番高かった価格 |
| low      | その期間の中で一番安かった価格 |
| close    | その期間の最後の価格           |
| volume   | その期間の取引量               |

各値は、既存の Kline モデルに合わせて String として保持します。

## 5. 処理仕様

処理は以下の順番で行います。

1. 入力値から読み込み対象のCSVファイルパスを取得する
2. CSVファイルの存在を確認する
3. CSVファイルを読み込む
4. 1行目をヘッダーとして読み込む
5. ヘッダーが openTime,open,high,low,close,volume の順番であることを確認する
6. 2行目以降をデータ行として読み込む
7. 空行は無視する
8. 各データ行を Kline に変換する
9. open, high, low, close, volume が数値として解釈できることを確認する
10. 読み込み完了後、openTime の昇順に並べる
11. openTime が重複するデータを1件にまとめる
12. List<Kline> として返す

## 6. 読み込むCSVの形式

読み込むCSVは、過去K線CSV作成機能で出力された形式を前提とします。

CSVヘッダー:

```
openTime,open,high,low,close,volume
```

opencsv により出力された、ダブルクォート付きのCSVも読み込めるようにします。

例:

```
"openTime","open","high","low","close","volume"
"1717200000000","10000000","10050000","9950000","10020000","12.5"
```

## 7. 並び順と重複の扱い

読み込んだK線データは、openTime の昇順に並べます。

入力CSVの行の並び順には依存しません。

同じ openTime のデータが複数存在する場合は、1件だけを返します。
採用するのは、CSV内で最初に出てきた行とします。

これにより、同じ時刻のK線が重複してバックテストに使われることを防ぎます。

## 8. エラー仕様

以下の場合はエラーとして扱います。

| 条件                                                          | 扱い         |
| ------------------------------------------------------------- | ------------ |
| CSVファイルパスが指定されていない                             | エラーにする |
| CSVファイルが存在しない                                       | エラーにする |
| CSVファイルを読み込めない                                     | エラーにする |
| ヘッダーが openTime,open,high,low,close,volume の順番ではない | エラーにする |
| 必須項目が空になっている                                      | エラーにする |
| open, high, low, close, volume が数値として解釈できない       | エラーにする |

エラー時は、可能な限り行番号と列名が分かるメッセージにします。

例:

CSVの3行目で close が空です。
CSVの5行目で open が数値として解釈できません: abc

## 9. 入力パスの扱い

BACKTEST_KLINE_CSV_PATH が相対パスの場合は、実行時のカレントディレクトリからの相対パスとして扱います。

例:

```
BACKTEST_KLINE_CSV_PATH=../../data/backtest/input/btc_5min_20260501_20260531.csv
```

この場合は、実行した場所から見た以下のCSVを読み込みます。

```
../../data/backtest/input/btc_5min_20260501_20260531.csv
```

BACKTEST_KLINE_CSV_PATH が絶対パスの場合は、そのまま使います。

## 10. 実装時の配置方針

実装時は、既存の責務分離に合わせて配置します。

| 層             | 役割                                |
| -------------- | ----------------------------------- |
| presentation   | 実行入口                            |
| application    | CSV読み込み処理の呼び出し順序を管理 |
| infrastructure | CSVファイル読み込み                 |
| domain         | 既存の Kline モデルを利用           |

読み込み用のインターフェースとして、domain.repository.KlineCsvReader を追加します。
ファイル読み込みの実装として、infrastructure.output.KlineCsvFileReader を追加します。

CSV読み込みには opencsv を使います。

domain には、ファイル読み込み処理を書きません。

## 11. 今後の実装順序

この仕様に沿って、次の順番で実装を進めます。

1. 過去K線CSV読み込み機能の仕様を追加する
2. 作成したCSVを読み込む機能を実装する
3. 読み込んだK線を使ってバックテスト本体を実装する
4. Strategyごとの比較結果を出力できるようにする
