# PLAN06: 定期実行での連続運転に移し、上限を段階的に上げる

**状態**: 未着手 / 前提: [PLAN05](plan05-canary-with-real-money.md) の実績

## なぜやるか

[PLAN05](plan05-canary-with-real-money.md) は「人が見ている時間に、手動でジョブを1回実行する」ところまでです。ここで定期実行に戻し、**人間が見ていない時間も含めて回し続ける**状態にします。これが「早く自動売買を動かしたい」という当初の目的の到達点です。

人が見ていない時間に出る不整合は、気づいたときには損失が確定しています。だから PLAN05 で監視下の実績を作ってからここに来ます。

## ゴール

定期実行で自動売買が回り続け、上限額を段階的に上げていける。

## 着手条件（[PLAN00](plan00-phase-and-safety-contract.md) で数字を確定させておく）

- [PLAN05](plan05-canary-with-real-money.md) で、不整合ゼロの売買サイクルが N 回連続で成立している。
- 想定外の停止が M 日間ゼロ。
- 通知・heartbeat・緊急停止が実際に機能したことを確認済み。
- 1日の損失上限、連敗停止、スリッページ上限が実装され、テストで動作を確認済み。

## 含む作業

1. Cloud Scheduler による定期実行に戻す（[スケジューラ設定](../operations/gcp/07-scheduler.md)）。
2. 無人運転で新たに効いてくる監視を用意する。
   - **一定時間 heartbeat が途切れたら気づける外部の仕組み。** アプリ自身は「自分が動いていないこと」を通知できません。ここだけは外から見る必要があります。
   - 保有したまま長時間動きが無い状態の検知。
3. 上限額を段階的に上げる手順と、各段階の判断基準を決める。1段階ごとに実績を見てから次に進みます。

## 受け入れ条件

- 定期実行で一定期間回り続け、記録の3点（取引所・`state.json`・通知）が一致し続けている。
- 損失上限・連敗停止が実際に発動して止まることを、テストで確認済み。
- ジョブが起動しなくなった場合に、外部の監視で気づける。

## 残るリスク（消えないもの）

- **5分間隔・API停止中・朝6時前後は、アプリ側の損切りが動きません。** 取引所側の逆指値などが使えないなら、その空白時間に耐えられる金額でしか運用できません。これは実装で消せるリスクではなく、**投入額で管理するリスク**です。
- 成行注文である以上、急変時のスリッページは避けられません。
- 相場が想定と違う動きをしたときに Strategy が損を出すことは、この計画の対象外です（[trading-safety-review](../../.agents/skills/trading-safety-review/SKILL.md) は「儲かるか」を扱いません）。
