# PLAN05: 最小額で実資金の1サイクルを通す（Phase3）

**状態**: 未着手 / 前提: [PLAN04](plan04-production-wiring-and-rehearsal.md) の完了

## なぜやるか

ここで初めて実資金が動きます。**目的は儲けることではなく、「買い → 保有 → 売り → 現金」が現実の取引所で記録どおりに完結することを、失っても構わない金額で確かめること**です。

## ゴール

人間が監視している状態で、最小額の実注文が1サイクル完結し、取引所の記録・`state.json`・通知の3つが完全に一致している。

## 着手条件（1つでも欠けたら着手しない）

- [ ] [PLAN01](plan01-real-sell-order.md): 売り注文が自動で出て、約定が state に反映される。
- [ ] [PLAN02](plan02-order-safety-guards.md): 最小注文数量、注文金額の上限、市場データ検証、重複実行抑止、発注 POST を再送しない、6時境界。
- [ ] [PLAN03](plan03-notification.md): 注文・約定・停止の通知が届く。自動停止（損失上限・連敗・スリッページ）が動く。
- [ ] [PLAN04](plan04-production-wiring-and-rehearsal.md): 障害シナリオが全部安全側に倒れ、数日の連続稼働で異常なし。
- [ ] [PLAN00](plan00-phase-and-safety-contract.md): 上限値・損失上限・緊急停止手順が決まって実装されている。**手動承認を置かない方針なので、ここが唯一の歯止めです。**
- [ ] 口座に入っている金額が、全額失っても困らない額に絞られている。
- [ ] 取引所の API キーに出金権限が付いていない。
- [ ] 緊急停止の手順を、実際に一度試して止まることを確認した。

## 実施手順

1. **口座に入れる金額を、上限値の合計程度に絞る。** 口座に入っていないお金は失えません。これが最後の、そして最も確実な防御です。
2. `config` を実注文用に切り替える。
   - `app.phase: 3`
   - `real_trading.dry_run: false`, `real_trading.real_trade_enabled: true`
   - `max_order_jpy` / `max_daily_order_jpy` / `max_position_jpy` を [PLAN00](plan00-phase-and-safety-contract.md) で決めた最小額にする
   - `trading.strategy_name` は許可した Strategy のみ、`order_sizing_mode: FIXED_AMOUNT`
3. **人が画面を見ている時間帯に、手動でジョブを1回実行する。** 定期実行から始めないでください。
4. 買い注文が出たら、取引所の管理画面で約定を確認する。`state.json` と通知の内容が一致していることを確認する。
5. 売り判定が出るまで保有し、売り注文が自動で出ることを確認する。出ない場合は原因を調べ、必要なら手動で決済する。
6. 1サイクル完結したら、記録の3点（取引所・`state.json`・通知）を突き合わせる。
7. 問題がなければ定期実行に戻し、数サイクル繰り返す。

## 受け入れ条件

- 実注文の買いと売りが、それぞれ取引所側で約定している。
- `state.json` の保有数量・買値・確定損益が、取引所の記録と一致している。
- 通知の内容が実際の注文と一致している。
- ダスト（端数）が残っていない、または残っても次の買いがブロックされない。
- 上限値を超える注文が1回も出ていない。
- 想定外の停止が起きた場合、通知が届き、[復旧手順](../operations/real-trading-recovery.md) どおりに復旧できる。

## 中止する条件

次のどれかが起きたら、**すぐ `real_trade_enabled: false` に戻して原因を調べてください。**

- `state.json` と取引所の記録が食い違った。
- 同じ判定で2回注文が出た。
- 売り注文が出るべき場面で出なかった。
- 上限値を超える注文が出た。
- 通知が来ない、または内容が実際と違う。

## やらないこと

- 金額を増やすこと。上限の引き上げは、複数サイクルの実績を見てから別途判断します。
- 定期実行での無人連続運転。それは [PLAN06](plan06-unattended-trading.md) です。ここでは人が見ている時間に手動実行から始めます。
