# 仕様策定支援

## 1. 目的

要求を実装可能・検証可能な仕様へ整理し、実装者が追加質問なしで着手できる状態にします。

## 2. 手順

1. 要件（Issue、チャット等）を読み、「目的 / スコープ / 非スコープ」に分類する。
2. 既存の仕様書（[docs/specifications/](../../../docs/specifications/)）や設計書（[docs/architecture/](../../../docs/architecture/)）、関連コードと照らし合わせ、矛盾や不足を抽出する。
3. 受け入れ条件を、テスト可能な形（Given / When / Then など）に変換する。
4. 未確定事項を「確認事項」として明確化する。

## 3. 制約

- **推測で仕様を決めないでください。** 不明点は必ず「確認事項」として挙げ、ユーザーに聞いてください。
- 既存の仕様と矛盾する場合は、どちらが正かを勝手に決めず、矛盾点として報告してください。

## 4. 出力

以下の項目を含むマークダウンで出力します。新しい仕様書ファイルを作る場合は、[docs/templates/specification-template.md](../../../docs/templates/specification-template.md) の形式に合わせてください。

- 仕様サマリ
- 受け入れ条件（テスト可能な形）
- 制約・前提
- 非スコープ
- オープンクエスチョン（確認事項）
