# コミットとPRの作成ルール

## 1. 変更粒度（PRを分けるかどうか）

- **1PR = 1つのユーザー価値、または1つの失敗モード改善**に限定します。
  - ユーザー価値: ユーザーにとって直接的な機能追加・改善。
  - 失敗モード改善: 障害パターン、再現性のある不具合、運用上の重大リスクを1つ解消する変更。
- **リファクタと機能追加は同一PRに混ぜません。** 依存関係がある場合は、次の順に分けます。
  1. リファクタPR（挙動を変えない）
  2. 機能追加PR（挙動を変える）
- レイヤをまたぐ変更の分割方針は [kotlin-layer-boundaries](../kotlin-layer-boundaries/SKILL.md) を参照してください。
- スコープ外の変更が混ざったら、PRを分割してください。分割しない判断をした場合は、理由と影響範囲をPR本文に書いてください。

## 2. コミットメッセージ

- 日本語で書きます。
- `feat:` `fix:` `docs:` `refactor:` `test:` `chore:` などの接頭辞は使って構いませんが、**接頭辞の後ろは必ず日本語**にします。
- 英語だけのメッセージ、内容が曖昧なメッセージは書きません。

**良い例**

- `docs: PRとコミットの作成ルールを追加`
- `fix: 注文金額の上限チェックが効かない不具合を修正`
- `chore: AIエージェント向けの作業ルールを整理`

**悪い例**

- `Update files` / `Fix bug` / `Changes` / `Improve docs`

## 3. PRタイトル

コミットメッセージと同じルールです。日本語で書き、接頭辞の後ろも日本語にします。英語だけ・曖昧なタイトルは禁止です。

## 4. PR本文

PR本文を書くときは、必ず次の順番で作業してください。

1. [.github/pull_request_template.md](../../../.github/pull_request_template.md) を読み直す。
2. テンプレートの見出し・順番・チェックボックスをそのまま使う。
3. 各項目に日本語で内容を書く。
4. 該当しない項目には `該当なし` と書く（項目自体は消さない）。
5. 実行していない確認やテストを、実行済みのように書かない。
6. 作成前に、テンプレートとPR本文を照合する。

**やってはいけないこと**

- テンプレートの見出しを削除する、並べ替える。
- テンプレートにない独自見出し（`備考`、`検証結果`、`リスク / 懸念点` など）を追加する。
- チェックボックスを削除する。
- 空欄のまま残す。
- チャットの完了報告用の内容をPR本文に混ぜる。

## 5. チャット報告とPR本文を分ける

- チャットでの完了報告（変更点 / 検証結果 / リスク）は [AGENTS.md](../../../AGENTS.md) の形式で書きます。
- PR本文の形式は `.github/pull_request_template.md` だけを正とします。
- 片方の形式をもう片方に持ち込まないでください。

## 6. 作成前の自己チェック

PRを作る前に確認し、1つでも満たしていなければ、PRを作らずに直してから作成してください。

- [ ] テンプレートの見出しがすべて残っているか
- [ ] 見出しの順番が変わっていないか
- [ ] チェックボックスが削除されていないか
- [ ] テンプレートにない独自見出しを追加していないか
- [ ] 空欄が残っていないか
- [ ] 該当しない項目に `該当なし` と書いているか
- [ ] PRタイトルとPR本文が日本語になっているか
- [ ] 実行していない確認を実行済みとして書いていないか
- [ ] このPRが「1つのユーザー価値」または「1つの失敗モード改善」に収まっているか
