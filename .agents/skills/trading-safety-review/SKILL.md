# 自動売買リスク監査

## 1. 目的

自動売買ロジックを損失制御の観点でレビューし、重大リスク（意図しない連続発注、異常値での取引、停止できない状態）を減らします。

**利益を上げるロジックの良し悪しは扱いません。** 異常事態でいかに損失を防ぐかだけに絞ります。

## 2. 手順

1. 損失シナリオを列挙する。少なくとも次を含めてください。
   - 価格の急変（急騰・急落、ヒゲ、異常値の混入）
   - 流動性の低下、板が薄い状態
   - GMO API の障害、タイムアウト、レート制限、想定外のレスポンス
   - ネットワーク切断、プロセス強制終了、途中再起動
   - 設定ミス（上限値の未設定、桁の間違い）
2. 既存コードのリスク制御を確認する。
   - 注文上限（`maxOrderJpy` / `maxDailyOrderJpy` / `maxPositionJpy`）
   - 損切り・利確の条件
   - 安全フラグ（`real_trade_enabled`, `dry_run`, `stop_on_order_error`, `stop_on_unconfirmed_order`）
   - 状態の永続化（`state.json`）と、再起動時の整合性
3. 「検知」「抑制」「停止」「復帰」の4観点でギャップを洗い出す。
   - 検知: 異常に気づけるか（ログ、閾値、応答検証）
   - 抑制: 被害を限定できるか（上限、クールダウン、1回あたりの露出）
   - 停止: 安全に止まれるか（例外時に発注を続けないか）
   - 復帰: 再開時に二重発注や状態不整合を起こさないか
4. 優先度をつけた改善案と、異常系テスト案を作る。

## 3. 判断の原則

- 迷ったら、**発注しない側・止まる側**を選びます。
- 未確認・不明な状態のまま次の注文に進まないでください。
- お金に関わる値にデフォルト値を入れないでください（[kotlin-code-rules](../kotlin-code-rules/SKILL.md) の「デフォルト値のルール」）。

## 4. 出力

- リスク評価サマリ（シナリオごとに、現状の防御と残存リスク）
- 未対策項目（優先度付き）
- 推奨する異常系テストケース（何を入力したら、何を期待するか）
